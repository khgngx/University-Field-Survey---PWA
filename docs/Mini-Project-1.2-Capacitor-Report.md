## 3. TECHNICAL ARCHITECTURE & PROJECT STRUCTURE

**Stack:** React 19 + Vite · Capacitor 8 (Android) · Dexie (IndexedDB) · Tailwind CSS 4 · Vercel Serverless + Supabase.

**Directory structure (Capacitor-related parts)**

```
capacitor.config.json    appId, appName, webDir
android/                 Native Android project generated by Capacitor (Gradle, manifest, icons)
scripts/build-apk.sh     Web build -> cap sync -> assembleDebug, with JDK/SDK checks
src/services/            The only code that imports Capacitor plugins
  camera.service.js        takePhoto()            -> compressed JPEG Blob or null
  scanner.service.js       scanRoomQr()           -> { building, floor, room } or null
  geo.service.js           getCurrentPosition()   -> { lat, lng, accuracy } or null
  network.service.js       getNetworkStatus(), onNetworkChange()
  notify.service.js        requestNotificationPermission(), notifySynced()
src/db/ · src/sync/      Storage and sync engine (no Capacitor imports)
src/pages/ · components/ UI, calls services only through plain async functions
```

**Layering**

```
React pages / hooks
        │  plain async functions returning plain data
        ▼
src/services/*.service.js ──► Capacitor plugin ──► native Android API
        │                          └── in a browser: web implementation / pwa-elements
        ▼
IndexedDB (Dexie) ──► sync queue ──► POST {VITE_API_URL}/surveys ──► Supabase
```

Pages never import a plugin directly. Each service returns ordinary values (a `Blob`, a location object, `null`), so the UI is identical on web and Android and the rest of the code can be unit-tested without a device (120 tests).

**State management flow**

IndexedDB is the single source of truth; there is no global state library. The wizard writes a draft (autosaved after 500 ms), Submit moves it to `PENDING_SYNC`, and the sync engine moves it through `SYNCING` to `SYNCED` or `FAILED`. The queue and dashboard pages subscribe with a Dexie live query and re-render on every change. Native plugins only feed this flow: the camera supplies the photo, the scanner the room, GPS the coordinates, and the Network plugin the trigger to sync.

**Exception handling strategy**

* **User cancels a native screen** (camera, scanner): detected and returned as `null`, so nothing is shown as an error.
* **Permission denied or hardware missing:** GPS and notifications are optional and never block a submit; camera and scanner errors are shown next to the button, and the QR image upload remains as a path that needs no camera.
* **GPS never hangs the form:** the plugin timeout is raced against a hard timer, because the permission dialog is not counted by the plugin's own timeout.
* **Sync errors are classified:** network errors, timeouts, 5xx, 408 and 429 are retried with backoff `min(2^n × 5 s, 5 min)` up to 5 times; other 4xx fail at once with the server's message and wait for a manual retry.
* **Interrupted sync:** a record left in `SYNCING` when the app was killed is re-queued at the next start.

## 5. TECHNICAL CHALLENGES & RESOLUTIONS

**Challenge 1 — The API could not be reached from inside the APK.**
On the web the app calls a relative `/api`, which works because the page and the API share one origin. Inside the Capacitor WebView the page is served from `https://localhost`, so the same relative path pointed at `https://localhost/api`, which does not exist, and every sync failed. Calling the real server instead is a cross-origin request, which the browser engine blocks unless the server allows it.
*Resolution:* the API base URL became a build-time setting (`VITE_API_URL`) that must be an absolute URL for the APK build, and the API's CORS allow-list always includes the WebView origin `https://localhost` (other origins come from an environment variable). The upload is also idempotent — the server upserts by the survey's UUID — so a retry after a half-finished request cannot create a duplicate.

**Challenge 2 — No background sync in the WebView, and a build that failed on the installed JDK.**
(a) The PWA uses the Service Worker Background Sync API to send queued surveys after the tab is closed, but that API does not exist in the Android WebView, so relying on it would leave surveys unsent on the APK. *Resolution:* background sync is treated as an optional extra. The main path is a set of in-app triggers that work everywhere: the Capacitor Network plugin's `networkStatusChange` event, the `online` event, a 30-second poll, a pass at app start, and a manual "Đồng bộ ngay" button. A lock prevents two runs from sending the same survey at once.
(b) Android Gradle Plugin 8.13 / Gradle 8.14 reject JDK 25, the system default, and the build stopped with an unclear error. *Resolution:* `scripts/build-apk.sh` looks for JDK 21 explicitly (`JAVA_HOME`, Homebrew, then `java_home -v 21`), verifies the Android SDK path, and exits with a one-line instruction when either is missing.
